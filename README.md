# AnimeHUB | Dream — Блич: навигация без перехода в бота (v4)

Эта версия **заменяет** старую версию `main.py` из DragonBall Style v3. В отличие от старого меню, подписчик **не переходит** в чат с ботом. Всё происходит в одном Telegram-канале «Блич».

## Как это работает

Бот публикует **3 сообщения** в указанном канале:

1. `⚔️ Блич (1–366)` — меню из 10 арок. Каждая кнопка открывает уже опубликованный пост в **том же** канале.
2. `🔥 Тысячелетняя кровавая война` — меню из 4 кнопок (Amber, DEEP, Прощание, Конфликт).
3. `⚔️ БЛИЧ — НАВИГАЦИЯ` — главное меню из двух кнопок, ведущих к двум сообщениям-разделам. Его можно закрепить.

В обоих меню арок будет кнопка **«⬅️ К основному меню»**, тоже ведущая к сообщению главного меню в канале.

Все кнопки — `url` c `t.me/c/3593534577/<ID>`, а не `callback_data` для изменения поста. Поэтому:

- зритель **не попадает в личный чат бота**;
- кнопки не меняют общий пост для остальных пользователей;
- переходы работают и в Telegram Desktop, и в Telegram Mobile;
- подписчик должен состоять в приватном канале, чтобы открыть ссылки `t.me/c/…`.

**Ограничение Telegram:** нельзя показывать разное содержимое одного и того же *канального* сообщения отдельно каждому зрителю с помощью обычных callback-кнопок: редактирование канального поста меняет его для всех. Поэтому использованы 3 отдельных сообщения и прямые ссылки.

## Что залить в GitHub

В корень текущего репозитория (без вложенной папки):

- `main.py` — **заменить старый**, где был переход `https://t.me/<bot>?start=...`;
- `catalog.json` — рядом с `main.py`, содержит все 14 ссылок пользователя. Если забыть его загрузить, бот всё равно запустится со встроенной копией каталога (но для редактирования лучше хранить отдельный файл);
- `requirements.txt`;
- `.gitignore`;
- `.env.example` (пример, не добавлять настоящие секреты).

Нельзя загружать `.env`, `state.json`, Telegram токен или Telegram-сессию в публичный репозиторий.

## BotHost

- Python **3.11**;
- главный файл **`main.py`**;
- Bot Token — новый бот из BotFather (BotHost передаст его как `BOT_TOKEN`);
- переменная `OWNER_USER_ID` — Telegram ID владельца;
- переменная `BLEACH_CHANNEL_ID` — `-1003593534577`;
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `SESSION_STRING` **не нужны**;
- Домены и Dockerfile не нужны.

В канале «Блич» назначить этого бота администратором с правами **публиковать**, **редактировать** и **закреплять сообщения**.

## Команды для первой публикации

От своего аккаунта в ЛС бота:

1. `/start` — справка;
2. `/status` — проверить, что бот видит **именно канал «Блич»**;
3. `/preview` — посмотреть обе категории с уже заданными ссылками без публикации;
4. `/post_nav` — подготовить публикацию;
5. `/confirm_nav` — опубликовать **3 сообщения**;
6. `/pin_nav` — закрепить верхнее меню.

Если старое меню v3 всё ещё закреплено, после публикации **открепить старый пост вручную**, чтобы подписчики использовали новое меню. Удаление старого меню необязательно, но поможет избежать путаницы.

## Команды для обновления

- `/links` — увидеть IDs всех 14 арок;
- `/setlink substitute https://t.me/c/3593534577/23` — пример изменения ссылки;
- `/update_nav` — применить изменения ко всем 3 сообщениям (важно: без этого опубликованные URL-кнопки не обновятся);
- `/set_nav 320 318 319` — восстановить ID трёх опубликованных меню после пересборки BotHost (**значения в примере вымышлены**; порядок: главное меню, оригинал, TYBW);
- `/pin_nav` — закрепить главное меню;
- `/cancel_nav` — отменить ожидаемую публикацию.

BotHost может удалять `state.json` при пересборке. Поэтому после первой публикации **сохрани ID 3 сообщений**, присланные ботом. Если они потеряются, восстанови их командой `/set_nav`. При смене ссылок также желательно отредактировать `catalog.json` в GitHub.

## Важно

`catalog.json` включает только **14 предоставленных тобой ссылок**; дополнительные арки или филлеры не добавлялись. Диапазоны серий сохранены как в твоих публикациях. Навигация работает без Premium и API ID/Hash. Реальный запуск и нажатия в Telegram необходимо проверить на своём канале.
